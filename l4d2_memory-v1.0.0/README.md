# L4D2 玩家状态 → DGHub

适用于《求生之路 2》的 Windows 外部只读玩家状态采集插件，通过 DGHub SDK v1 将游戏状态映射为波形反馈和强度变化。无需房主安装服务端插件。

**作者：MMFelix · 版本：v1.0.0 · 发布日期：2026-10-19**

## 功能

- 读取本地生还者的实际血量、临时血量、倒地、挂边、生命状态及特感控制关系。
- 10 项反馈独立配置：开关、波形、持续时间、通道、事件期间最低强度及冷却。
- 倒地期间可持续反馈；扶起、死亡、挂边或数据失效后停止续播，最后一段最多保留 0.5 秒。
- 支持动态、固定、挑战三种基础强度模式。
- 自动等待游戏、检查模块版本、过滤重复快照；状态读取失败时清零本插件强度层。
- 随附离线配置预览、诊断工具和自动测试。

黑白、被扶起、回血、复活均不提供事件反馈或设置项。治疗和复活仍会更新内部血量与生命周期，确保动态强度、倒地停止及挑战重置正常工作。

## 环境与兼容性

| 项目 | 要求 |
| --- | --- |
| 系统 | Windows |
| 主程序 | 支持外部插件 SDK v1 的 DGHub；本机测试版本为 1.9.10 |
| 游戏 | 本发布包提供 L4D2 2.2.4.3 的 32 位游戏进程地址配置 |
| 玩家 | 本地玩家为生还者 |
| 依赖 | 通过 DGHub 启动时使用其插件运行环境及 websockets 依赖 |

地址配置绑定 client.dll 的 SHA-256：

```text
c0a8e1e88f7312db11bcfd4b0ec574d224a34b2d9a615d6088b28335eeb4af1f
```

相同游戏版本号也可能对应不同模块文件。指纹不符时会暂停读取，其他版本需要重新验证地址配置。

插件使用标准 Windows 只读进程接口，不修改游戏内存，不提供进程隐藏、注入、驱动或反作弊绕过功能；不保证反作弊兼容性。

## 安装与开始使用

1. 下载发布附件 `l4d2_memory-v1.0.0.zip`，在 DGHub 插件中心导入。
2. 启用 **L4D2 玩家状态（外部采集）**，并确认 DGHub 当前输出设备在线。
3. 进入游戏对局，检查插件状态卡片中的血量和玩家状态是否正确。
4. 在各事件设置中选择 DGHub 已有的波形预设，配置时长及通道。
5. 确认读数后关闭 **仅观察状态**，开始输出。

首次安装默认开启仅观察模式，不向设备发送控制消息；事件默认没有选择波形。没有选择预设时只显示事件卡片。输出目标跟随 DGHub 当前设备。

升级已有安装会沿用主程序保存的有效配置。旧版已删除事件的配置即使仍保存在主程序中，也会被本插件忽略。请避免与其他同类插件同时触发重复反馈。

## 反馈事件

| 事件 | 触发条件 | 行为 |
| --- | --- | --- |
| 受伤 | 普通存活阶段有效生命值下降 | 单次反馈，补偿临时血量自然衰减 |
| 倒地 | 进入倒地，排除挂边 | 默认持续反馈，也可设为单次 |
| 挂边 | 进入挂边 | 单次反馈 |
| Smoker 控制 | 有效舌头拥有者句柄出现 | 单次反馈 |
| Hunter 扑倒 | 有效扑倒攻击者句柄出现 | 单次反馈 |
| Jockey 骑乘 | 有效骑乘攻击者句柄出现 | 单次反馈 |
| Charger 携带 | 进入携带阶段 | 单次反馈 |
| Charger 砸地 | 进入砸地阶段 | 单次反馈 |
| 死亡 | 同一玩家由存活变为濒死或死亡 | 单次反馈，默认 3 秒 |
| 脱离控制 | 所有特感控制关系解除 | 单次反馈；控制阶段切换不算脱离 |

特感句柄会校验实体索引、序列号、攻击者队伍与生命状态。其他控制事件只在进入状态时触发，持续时长由事件配置决定。

## 强度与波形

基础强度和事件波形独立管理，所有强度均受本插件上限约束。

| 模式 | 行为 |
| --- | --- |
| 动态 | 损失有效生命值 × 每 HP 百分比；满血为 0，治疗降低，倒地或挂边使用上限 |
| 固定 | 保持配置的固定强度，包括死亡阶段 |
| 挑战 | 累计观察到的站立生命值损失；治疗不降低，死亡保留，复活或新会话重置 |

动态模式死亡后保留先前强度至死亡事件时长结束，随后清零。数据过期规则优先，因此数据失效时可能提前结束。倒地血量池与站立血量分开处理，避免把倒地后的血量重置误计为治疗或巨大伤害。

“事件期间最低强度”与基础强度取较高值，不累加，到期恢复基础层。设置为 0 表示仅使用基础强度。关闭某个事件仅关闭其反馈，不会关闭血量驱动的基础强度。

插件通过 `set_strength` 管理自己的绝对强度层，通过 `trigger(action=waveform)` 播放波形。因此波形不参与 DGHub 的高强度事件音效判断。清零仅作用于本插件层，其他插件仍可能保持输出。

## 采集与已知限制

- 默认 120 Hz 轮询；观察本地预测 tick、模拟时间和玩家指针。标记不变时每 0.1 秒复查完整状态。
- 读取前后复查标记，丢弃跨更新快照；这不是游戏内存锁，不保证原子快照或捕获每个服务器 tick。
- 采用单个常驻采集线程。等待游戏低频重试，数据停止更新后降低轮询；状态无变化时最多每 15 秒上报心跳。
- 默认数据过期时间为 1.5 秒。暂停游戏、切换窗口导致单机暂停、切图、读数失败等可能使输出清零。恢复首帧建立基线，不补播历史事件。
- 会话依据进程身份、玩家指针和游戏时钟变化判断，没有独立的地图身份或 engine signon 判据。
- 客户端血量差无法还原完整受伤事件；两次采样之间的多次伤害和治疗可能合并或抵消。
- 临时血量衰减默认 0.27 HP/秒，修改规则的服务器需要按实际情况调整。
- 未提供燃烧、酸液等伤害类型分类，也未提供闪光或烟雾事件。

本机已核对 100 → 93 HP 读数，倒地持续反馈已获得实际体验确认；死亡标志变化已捕获，死亡回退逻辑已通过模拟测试。死亡波形修复后的实际设备反馈、全部特感控制、挂边、换图及远程服务器组合仍需进一步验证。版本号 v1.0.0 不代表所有场景已完成实机验证。

## 常见问题

**显示等待游戏或等待进入对局**：确认游戏已启动并进入对局，本地玩家为生还者。

**提示模块版本不符**：当前游戏文件与随包地址配置不一致，需要重新验证配置，不建议跳过指纹检查。

**读数正常但没有设备反馈**：检查仅观察开关、DGHub 输出目标是否在线、事件是否启用及波形是否已选择。动态模式满血时基础强度为 0。

**倒地结束还有很短的尾音**：持续反馈采用最长 0.5 秒的短波形段，停止续播后最后一段到期结束。死亡波形属于独立事件。

## 源码开发与打包

在 Windows 源码目录使用 Python 3.11 或更新版本，并安装 websockets：

```powershell
python -m pip install websockets
python -m unittest discover -s tests -p test_plugin.py
python build.py
python package.py
```

`build.py` 生成 manifest 和离线预览；`package.py` 使用明确的文件清单构建 ZIP，并生成 SHA-256 校验文件。发布包根目录直接包含 manifest.json，可供 DGHub 导入。

诊断命令不连接 DGHub，不发送设备命令：

```powershell
python diagnose.py --output game-diagnostics.json
python diagnose.py --profile profiles/game.json --seconds 10
python discover.py
```

属性发现工具会输出候选地址，候选不是已验证配置。`prepare_profile.py` 仅重建本次适配版本，并非通用自动适配器。

## 项目说明

本插件遵循 DGHub SDK v1 的 JSON over WebSocket 外部进程协议。开发中参考了 `yufun-meow/l4d2-dghub` 的服务端事件联动思路，本项目采用本地只读采集方式。

源码上传请使用发布 ZIP 解压后的文件，避免上传本机浏览器缓存、运行日志、候选地址及私人配置。自动打包已排除这些本地文件。
